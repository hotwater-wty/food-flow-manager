# 页面地图与交互状态

> 状态：当前事实（2026-08-29，以 `apps/*/src/router/index.ts` 为准）

## 0. 工程形态

前端为 pnpm workspace 双应用：`apps/customer`（顾客端，Vant，dev 端口 5174）与 `apps/admin`（商户端，Element Plus，dev 端口 5173），共享契约包 `packages/shared`（types + utils）。两端互不引用对方页面，登录页与 404 各自独立于布局；生产域名和 nginx 尚未落地。

## 1. 路由树

### 顾客端 apps/customer（前缀旧地址 /customer/** 自动去前缀重定向）

## 2. 守卫与权限

| meta | 应用 | 触发条件 | 行为 |
| --- | --- | --- | --- |
| `requiresAuth` | customer | 顾客 Token 缺失 | 重定向 `/login?redirect=原路径`，登录后回跳 |
| `requiresAdminAuth` | admin | 员工 Token 缺失 | 重定向 `/login?redirect=原路径`，登录后回跳 |
| `requiresManager` | admin | 已登录但角色非店长(role≠2) | 重定向到 `/orders`(订单工作台) |

拆分后每个应用只有一个认证域:customer 只持有顾客 JWT、admin 只持有员工 JWT,互不可见。界面层的显隐只是体验优化;后端 JWT 拦截器始终是最终防线。

## 3. 页面职责

### 顾客端(Vant,移动优先)

- `首页`:未登录时只显示登录与预约入口，不请求受保护桌位接口；登录后查询当前会话和空闲桌位，选择并确认后开台。
- `选择座位`:兼容入口，与首页复用同一个选座/开台组件；已有进行中会话时只显示绑定桌位和去点餐入口。
- `菜单点餐`:分类 Tabs、菜品卡片(图片失败占位)、Stepper 加购;无会话时顶部提示条引导回首页选座;有会话时底部 SubmitBar 显示明细与合计并可下单。
- `我的订单`:订单卡片列表、状态 Tag、"查看明细"内嵌展开。
- `我的预约`:预约卡片、状态 Tag、详情弹层、待到店预约可取消或到店开台。
- `发起预约`:桌位卡片选择、人数 Stepper、datetime-local 时间选择,VanForm 规则校验。
- `我的账户`:账户信息卡、服务入口、用户 ID 与退出登录确认。

### 商户端(Element Plus,桌面优先)

- `经营概览`:今日订单数/营收卡片、状态分布条、热销 TOP 榜；收到布局级 SSE 外部变化通知后静默刷新。
- `订单处理`:状态筛选下拉、ElTable、分页、详情抽屉、终态完成确认；写入由统一 loading/通知/刷新流程处理。
- `会话与桌台`:状态筛选、会话/桌位双状态列、详情抽屉、取消等待/清台确认；外部变化由 SSE 提示并重新查询。
- 资料维护五个子页:统一 ElTable+ElPagination+ElDialog 表单;桌位与员工仅店长可见;菜品含 ElImage 图片列、分类下拉、价格元↔分换算;预约为只读为主的管理视角。

## 4. 必须覆盖的状态

| 场景 | UI 行为 |
| --- | --- |
| loading | 页面保留稳定布局，显示加载指示，不闪烁空状态 |
| 空列表 | 给出原因和下一步入口，不伪造数据 |
| 请求失败 | 展示后端 `msg`，提供重试 |
| 静默刷新失败 | 保留当前数据,仅 console 记录,等下一轮重试 |
| 401/Token 过期 | 清除认证状态，回到本端登录页 |
| 403/角色不足 | 店员不渲染店长专属入口，直达被守卫拦回订单页 |
| 重复提交 | 按钮进入 loading，令牌只使用一次 |
| 业务冲突 | 展示后端错误，刷新相关实体状态 |
| 无当前会话 | 顾客端允许浏览菜单但不渲染购物车栏，提示条引导去开台 |
| 管理端写成功 | 显示业务化成功通知，立即重新查询；`data=null` 仍为成功 |
| 管理端写失败 | 显示可点击错误通知，详情对话框展示稳定错误码、HTTP 状态、请求与发生时间 |
| SSE 外部变化 | 管理布局唯一连接广播事件，关联页面静默重新查询；不承担按钮操作反馈 |

## 5. 状态映射

- 桌位：`0 空闲`、`1 已预约`、`2 等待中`、`3 用餐中`、`4 禁用`。
- 预约：`0 待到店`、`1 已到店`、`2 已取消`、`3 已超时`。
- 会话：`0 等待中`、`1 用餐中`、`2 已完成`、`3 已取消`。
- 订单：`1 已下单`、`2 制作中`、`3 已上齐`、`4 已完成`、`5 已取消`。
- 菜品：`0 停售`、`1 启售`、`2 售罄`。

唯一权威实现:类型与映射表在 `packages/shared/src/`(types/api.ts、utils/status.ts、utils/order-status.ts、utils/format.ts),双应用经 `@foodflow/shared/*` 引用。

## 6. 视口约定

商户端按 1440x900 设计（侧栏两级菜单树+顶栏）；顾客端按 390x844 移动优先设计（顶栏+VanTabbar 底部导航），窄屏下商户端侧栏折叠为横向菜单。
