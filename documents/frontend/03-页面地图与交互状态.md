# 页面地图与交互状态

> 状态：当前事实（2026-08-27 二期收口后重写，以 [`frontend/src/router/index.ts`](../../frontend/src/router/index.ts) 为准）

## 1. 路由树

路由为"布局父路由 + 页面子路由"的嵌套结构；顾客页共用 `CustomerLayout`，管理页共用 `AdminLayout`，两个登录页和 404 不进布局。

```text
/                                    首页(顾客入口引导)                CustomerLayout
/customer/login                      顾客登录/注册                     无布局
/customer/account                    我的账户(账户中心)      登录       CustomerLayout
/customer/session                    扫码开台              登录       CustomerLayout
/customer/menu                       菜单点餐              登录       CustomerLayout
/customer/orders                     我的订单              登录       CustomerLayout
/customer/reservations               我的预约              登录       CustomerLayout
/customer/reservations/create        发起预约              登录       CustomerLayout

/admin/login                         员工登录                          无布局
/admin/orders                        订单处理              员工        AdminLayout
/admin/sessions                      会话与桌台             员工        AdminLayout
/admin/resources                     -> 重定向到桌位维护页
/admin/resources/tables              桌位维护     员工+店长   AdminLayout
/admin/resources/categories          菜品分类     员工        AdminLayout
/admin/resources/dishes              菜品维护     员工        AdminLayout
/admin/resources/reservations        预约管理     员工        AdminLayout
/admin/resources/employees           员工管理     员工+店长   AdminLayout

/:pathMatch(.*)*                     404 兜底页                        无布局
```

## 2. 守卫与权限

| meta | 触发条件 | 行为 |
| --- | --- | --- |
| `requiresAuth` | 顾客 Token 缺失 | 重定向 `/customer/login?redirect=原路径`，登录后回跳 |
| `requiresAdminAuth` | 员工 Token 缺失 | 重定向 `/admin/login?redirect=原路径`，登录后回跳 |
| `requiresManager` | 已登录但角色非店长(role≠2) | 重定向到 `/admin/orders`(订单工作台) |

两类 Token 由两个 Pinia Store 分开保存、分开校验，避免一类凭证被误当成另一类身份。界面层的显隐只是体验优化；后端 JWT 拦截器始终是最终防线。

## 3. 页面职责

### 顾客端(Vant,移动优先)

- `首页`:欢迎语、点餐/预约双入口、三步使用引导、员工管理端入口。
- `扫码开台`:展示桌位卡片并调用开台接口;已有进行中会话时显示会话恢复面板。
- `菜单点餐`:分类 Tabs、菜品卡片(图片失败占位)、Stepper 加购;无会话时顶部提示条引导开台;有会话时底部 SubmitBar 显示明细与合计并可下单。
- `我的订单`:订单卡片列表、状态 Tag、"查看明细"内嵌展开。
- `我的预约`:预约卡片、状态 Tag、详情弹层、待到店预约可取消或到店开台。
- `发起预约`:桌位卡片选择、人数 Stepper、datetime-local 时间选择,VanForm 规则校验。
- `我的账户`:账户信息卡、服务入口、用户 ID 与退出登录确认。

### 管理端(Element Plus,桌面优先)

- `订单处理`:状态筛选下拉、ElTable、分页、详情抽屉(ElDescriptions+菜品明细表)、终态完成确认。
- `会话与桌台`:状态筛选、会话/桌位双状态列、详情抽屉、取消等待/清台确认。
- 资料维护五个子页:统一 ElTable+ElPagination+ElDialog 表单;桌位与员工仅店长可见;菜品含 ElImage 图片列、分类下拉、价格元↔分换算;预约为只读为主的管理视角。

## 4. 必须覆盖的状态

| 场景 | UI 行为 |
| --- | --- |
| loading | 页面保留稳定布局，显示加载指示，不闪烁空状态 |
| 空列表 | 给出原因和下一步入口，不伪造数据 |
| 请求失败 | 展示后端 `msg`，提供重试 |
| 401/Token 过期 | 清除认证状态，回到对应登录页 |
| 403/角色不足 | 店员不渲染店长专属入口，直达被守卫拦回订单页 |
| 重复提交 | 按钮进入 loading，令牌只使用一次 |
| 业务冲突 | 展示后端错误，刷新相关实体状态 |
| 无当前会话 | 允许浏览菜单但不渲染购物车栏，提示条引导去开台 |

## 5. 状态映射

- 桌位：`0 空闲`、`1 已预约`、`2 等待中`、`3 用餐中`、`4 禁用`。
- 预约：`0 待到店`、`1 已到店`、`2 已取消`、`3 已超时`。
- 会话：`0 等待中`、`1 用餐中`、`2 已完成`、`3 已取消`。
- 订单：`1 已下单`、`2 制作中`、`3 已上齐`、`4 已完成`、`5 已取消`。
- 菜品：`0 停售`、`1 启售`、`2 售罄`。

前端唯一权威映射表在 [`frontend/src/utils/status.ts`](../../frontend/src/utils/status.ts)；时间展示统一去掉 ISO 的 `T`（[`frontend/src/utils/format.ts`](../../frontend/src/utils/format.ts)）。

## 6. 视口约定

管理端按 1440x900 设计（侧栏两级菜单树+顶栏）；顾客端按 390x844 移动优先设计（顶栏+VanTabbar 底部导航），窄屏下管理端侧栏折叠为横向菜单。
