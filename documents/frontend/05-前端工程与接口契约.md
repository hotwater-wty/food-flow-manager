# 前端工程与接口契约

> 文档状态：当前目标规格
> 实现状态：顾客登录、Token 持久化、认证状态恢复、请求自动鉴权和路由保护已接入
> 后端事实入口：[`../architecture/backend/核心接口清单设计.md`](../architecture/backend/核心接口清单设计.md)

## 1. 请求层

Axios baseURL 使用环境变量 `VITE_API_BASE_URL`，开发环境默认为空并由 Vite 将 `/api` 代理到 `http://localhost:8080`。

后端当前响应统一为：

```ts
type Result<T> = { code: 1 | 0; msg: string; data: T | null }
```

请求层只在 `code === 1` 时返回 `data`；`code === 0` 抛出后端 `msg`。HTTP 401 会清理认证状态并跳转顾客登录页；HTTP 403 保留给调用方处理。

## 2. 鉴权与防重复提交

顾客登录结果由认证 Store 拆分为用户信息和 Token，并以 `food-flow-manager.customer-auth` 为键写入 `localStorage`；应用启动时同步恢复，退出登录时同时清除内存状态和持久化数据。认证请求拦截器会在存在 Token 时以 `Bearer` 形式放入 `Authorization`。

路由使用 `meta.requiresAuth` 标记受保护页面；路由守卫只改善前端导航体验，真正的安全边界仍由后端 JWT 拦截器提供。当前 `/customer/account` 是用于验证认证边界的最小受保护页面。

用户端 `GET /api/user/tables` 返回当前空闲桌位数组，预约页使用 `tableId/tableNo/capacity/locationDesc` 展示和校验。创建预约前先调用 `POST /api/user/submit-token`，请求体为 `{ scene: "create-reservation" }`；再调用 `POST /api/user/reservations`，字段为 `tableId/peopleCount/reserveTime`，时间格式为 `yyyy-MM-dd HH:mm:ss`，并通过 `X-Submit-Token` 携带一次性令牌。创建成功后以前端展示后端返回的预约编号为准。

预约查询使用 `GET /api/user/reservations`、`GET /api/user/reservations/{reservationId}/detail`；取消使用 `POST /api/user/reservations/{reservationId}/cancel`，当前后端仅允许待到店预约取消，前端只对状态 `0` 展示取消操作。

创建预约和创建订单前，调用 `POST /api/user/submit-token`，场景分别为 `create-reservation` 和 `create-order`，把返回令牌放入 `X-Submit-Token`。令牌 TTL 为 5 分钟且消费一次，不能自动复用旧令牌重试。后端枚举还定义 `open-session`、`clear-table`，但当前开台和清台 Controller 尚未接入令牌校验，前端不得自行假设已启用。

用户端开台接口：`POST /api/user/tables/{tableId}/sessions` 用于非预约用户模拟扫码开台；预约到店使用 `POST /api/user/reservations/{reservationId}/check-in/{tableId}`。当前会话通过 `GET /api/user/sessions/current` 查询，响应字段为 `sessionId/sessionNo/tableId/tableNo/sessionStatus/tableStatus`。开台接口当前不要求 `X-Submit-Token`。

预约到店开台只能使用预约返回的 `tableId`，后端要求预约状态为待到店、扫码桌位状态为已预约且桌位 ID 与预约一致；成功后预约变为已到店，桌位进入等待状态并创建当前会话。

菜单接口：`GET /api/user/dish-categories` 返回启用分类，`GET /api/user/dishes` 返回启售菜品，可通过 `categoryId` 查询参数筛选；菜品字段为 `id/categoryId/name/price/image/description/status`，其中 `price` 单位为分。订单创建另见 `POST /api/user/sessions/{sessionId}/orders`，要求 `X-Submit-Token`，本阶段暂不调用。

## 3. 数据约定

- JSON 使用小驼峰。
- 金额接口单位为分，展示时除以 100 并保留两位。
- 时间格式为 `yyyy-MM-dd HH:mm:ss`。
- ID 用于接口路径；预约号、订单号、会话号用于展示和沟通。
- 管理端分页字段为 `total`、`pageNo`、`pageSize`、`records`；用户端订单、预约、菜品、分类和桌位列表当前按普通数组返回。

## 4. 前端类型边界

`src/types/api.ts` 对应后端 VO/DTO；`src/utils/status.ts` 集中维护状态数字和文案；模板禁止直接出现状态魔法数字。

## 5. 后端配套边界

开发期优先用 Vite 代理，不要求立即修改 CORS。若真实部署需要跨域，只允许增加明确来源的 CORS 配置，不允许放开任意来源并携带凭证。
