# 前端项目决策总览

## 1. 项目定位

膳畅管家前端是一个学习型、可展示、可实际演示的餐饮预约与堂食管理界面。目标不是做完整餐饮 SaaS，而是把已有后端业务组织成两种角色都能理解的使用体验。

## 2. 角色与设备

| 角色 | 主要任务 | 首选设备 |
| --- | --- | --- |
| 顾客 | 预约桌位、模拟扫码开台、浏览菜单、点餐、查看订单 | 手机 |
| 店员 | 查看订单、推进状态、查看会话、清台 | 电脑 |
| 店长 | 店员能力 + 后台资料管理 | 电脑 |

## 3. 技术决策

- Vue 3 + TypeScript + Vite：学习成本可控，类型边界清楚。
- Pinia：保存认证信息、当前会话和顾客购物车。
- Vue Router：按 `/customer` 与 `/admin` 分开路由和权限。
- Axios：集中处理 JWT、统一响应和错误。
- Vant：顾客端移动交互。
- Element Plus：商户端表格、表单、抽屉和分页。
- `pnpm`：锁定依赖并提供快速安装。

## 4. 首版边界

首版必须完成顾客和商户各一条纵向闭环；桌位、菜品、分类、员工 CRUD 是第二批。首版不做支付、真实二维码、短信、退单、改单、催单、多门店、排班和库存。

## 5. 后端协作边界

前端复用现有 `/api/user`、`/api/admin` 接口和 `Result<T>` 响应。允许的后端配套改动仅限 CORS、契约缺口、开发数据和健康检查，不改变状态机、权限和核心业务规则。
