# 前端项目决策总览

## 1. 项目定位

膳畅管家前端是一个学习型、可展示、可实际演示的餐饮预约与堂食管理界面。目标不是做完整餐饮 SaaS，而是把已有后端业务组织成两种角色都能理解的使用体验。

## 2. 角色与设备

| 角色 | 主要任务 | 首选设备 |
| --- | --- | --- |
| 顾客 | 预约桌位、首页选择空闲桌位开台、浏览菜单、点餐、查看订单 | 手机 |
| 店员 | 查看订单、推进状态、查看会话、清台 | 电脑 |
| 店长 | 店员能力 + 后台资料管理 | 电脑 |

## 3. 技术决策

- Vue 3 + TypeScript + Vite：学习成本可控，类型边界清楚。
- Pinia：保存认证信息、顾客购物车、管理端通知和操作反馈状态。
- Vue Router：顾客端与商户端独立路由、独立守卫；旧前缀地址只做兼容重定向。
- Axios：集中处理 JWT、统一响应和错误。
- Vant：顾客端移动交互。
- Element Plus：商户端表格、表单、抽屉和分页。
- `pnpm`：锁定依赖并提供快速安装。

## 4. 首版边界

顾客和商户主闭环、桌位/菜品/分类/员工资料维护均已完成。支付、真实二维码、短信、退单/改单、多门店、排班和库存仍不是当前已实现能力；后续优先级以项目发展计划为准。

## 5. 后端协作边界

前端复用 `/api/user`、`/api/admin` 接口和 `Result<T>` 响应。涉及状态机、权限或核心业务规则的后端改动必须先更新契约与当前计划，并同时设计自动化测试。
