# 前端拆分(S1-S4)验收记录

> 验收日期:2026-08-28
> 范围:单 Vite 应用拆分为 pnpm workspace 双应用(apps/admin + apps/customer + packages/shared),开发期以 5173/5174 端口区分,未引入 nginx
> 计划依据:[`../frontend/08-双端拆分准备评估.md`](../frontend/08-双端拆分准备评估.md)

## 交付结构

```
food-flow-manager/
├── apps/
│   ├── admin/       # 商户端 @foodflow/admin:Element Plus,dev 5173
│   └── customer/    # 顾客端 @foodflow/customer:Vant,dev 5174
├── packages/shared/ # @foodflow/shared:types/api + utils(format/status/order-status),TS 源码直引
├── pnpm-workspace.yaml
└── package.json     # 根脚本:dev:admin / dev:customer / type-check / build / verify:api
```

## 关键变化

| 项 | 拆分前 | 拆分后 |
| --- | --- | --- |
| 路由 | 单路由表双域,admin 带 `/admin` 前缀 | 双路由表,admin 根路径即工作台;`/admin/**`、`/customer/**` 旧地址各有兜底重定向 |
| http 拦截器 | 单实例按 URL 前缀嗅探双 token、按路由路径嗅探跳登录 | 双实例各自单 token、直跳各自 `/login`,嗅探逻辑删除 |
| 互通 | 商户端品牌位/登录页/404/首页均可跳顾客端 | 全部移除;`RouterLink` 物理上指向不到另一 origin |
| 依赖 | 双 UI 库全量共存于一个 main.ts | admin 仅 Element Plus(customer 仅 Vant),互不安装 |
| token 隔离 | 同 origin 靠 storage key 命名隔离 | 两 dev server 暂同 localhost,生产双域名后为 origin 级隔离(结构性) |
| 主包体积 | 单端 gzip 约 351KB(双库全量) | admin 主包 964K / customer 主包 392K(未压缩,双端各自只剩一个 UI 库) |

## 验收证据

- 双端 `vue-tsc -b`、`vite build` 退出码 0;`node apps/admin/scripts/smoke-api.mjs` 通过;`git diff --check` 干净。
- 浏览器走查(DOM 快照断言):
  - 商户端 5173:登录 → `/orders` 工作台渲染订单数据;菜单 8 项全部为新路径(`/dashboard`、`/orders`…);经营概览卡片渲染;退出登录回 `/login`;登录页与 404 无任何顾客端链接;品牌位点击留在商户端。
  - 顾客端 5174:首页 Tabbar 四项渲染;登录后跳 `/menu`,登录态昵称上顶栏;点餐/订单 Tab 导航正常;404 兜底页正常。
  - 旧地址重定向双端验证:`5173/admin/resources/employees` → `/resources/employees`(员工管理页渲染);`5174/customer/reservations` → `/reservations`。
- 过程中修复(预测外问题,顺手解决):
  1. **菜单硬编码旧路径**:AdminLayout 菜单项仍是 `/admin/**`,改为新路径;
  2. **redirect 缺前导斜杠 + pathMatch 是数组**:`path: to.params.pathMatch` 被当相对路径、模板字符串拼出 `resources,employees` 逗号串——用 `Array.join('/')` + `/${rest}` 修复,并先用 vue-router 内存路由单元实测再上浏览器验证。

## 已知边界

- 5173/5174 同属 localhost,storage 仍共享 origin;结构性隔离要等生产双域名(nginx 部署时,需单独授权)。
- `use-pagedList` 只保留在 admin(customer 无分页列表);customer 的 `stores/app.ts` 为历史占位未删。
