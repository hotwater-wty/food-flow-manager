# P0-5 业务错误码注册表验收记录

> 验收日期：2026-08-30
> 范围：核心业务异常稳定错误码
> 计划：[`../../planning/project-development-plan.md`](../../planning/project-development-plan.md)

## 1. 实现内容

- 新增 `BusinessErrorCode` 枚举，集中登记错误码、默认提示、所属领域、是否可重试和建议 HTTP 状态。
- `BusinessException` 新增直接接收错误码枚举的构造器，同时保留字符串构造器，便于后续分批迁移。
- 桌位、预约、会话、订单、提交令牌和提交场景已改用注册表中的稳定编码。
- 保留原有用户可读中文提示；机器端应使用 `Result.errorCode`，不依赖 `msg` 文本。

## 2. 测试与验收

`BusinessErrorCodeTest` 验证编码唯一、元数据完整，以及异常构造器能正确传递编码和默认消息。核心状态机测试同时验证桌位占用和非法订单状态的错误码。

```bash
cd backend
./mvnw -q test
```

## 3. 当前边界

- 员工、顾客、菜品和分类等低频业务异常仍有部分使用通用 `BUSINESS_ERROR`，后续可按前端展示和运营统计价值继续迁移。
- 缓存解析、缓存键为空等基础设施异常暂不归入业务错误码；发生时应由系统异常或专门的基础设施错误治理处理。
- 错误码注册表不是 HTTP 状态码替代品；认证失败、权限失败和协议错误仍需遵守 HTTP 层边界。
