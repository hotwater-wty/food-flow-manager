## 1. 实现内容

新增 `backend/src/test/java/com/foodflow/CoreStateMachineIntegrationTest.java`，使用完整 Spring Boot 上下文、真实 Service、MyBatis Mapper 和 Testcontainers 提供的 MySQL/Redis，测试结束后通过 `@Transactional` 回滚测试数据，并在每次测试后清理线程级 `LoginContext`。

## 2. 覆盖场景

| 场景 | 关键断言 |
| --- | --- |
| 预约创建并取消 | 桌位 `FREE -> RESERVED`；取消后恢复 `FREE`；预约变为 `CANCELED` |
| 预约占用冲突 | 第二个用户预约失败；原预约、桌位状态和预约数量不变 |
| 首单创建 | 会话和桌位 `WAITING -> DINING`；订单金额、状态和订单明细快照正确 |
| 非法订单跳跃 | `PLACED` 不能直接跳到 `SERVED`；订单保持原状态 |
| 完成订单并清台 | 订单推进到 `SERVED` 后清台；会话 `COMPLETED`、订单 `COMPLETED`、桌位 `FREE` 且解绑当前会话 |

## 4. 当前边界

- 当前重点是单线程状态流转和多表最终一致性，尚未覆盖并发预约竞态、事务中途异常回滚、HTTP Controller 权限和真实网络超时。
- 失败断言仍包含现有中文消息；P0-5 建立稳定业务错误码后，应优先断言 `errorCode`，消息只作为用户可读文案的辅助断言。
- 测试数据使用唯一手机号、桌号和菜品名，避免依赖固定自增 ID；新增场景应保持同样的隔离原则。
