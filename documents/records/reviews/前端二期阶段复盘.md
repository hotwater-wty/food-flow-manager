## 三、本阶段的关键经验教训

1. **"构建通过"不等于"类型检查通过"**：根 tsconfig 是 `"files": []` 引用结构时，`vue-tsc --noEmit` 实际什么都没查,R1-R4 的该条证据因此空转。最终以 `vue-tsc -b` 替换并立即暴露 4 个真实错误。教训:验收命令本身也要验收——新增脚手架命令时应确认它确实覆盖了目标文件。
2. **组件库默认行为要么全用要么自管**：VanTabbar 不开 route 模式又不绑 v-model 时,高亮恒为第一项;只靠 CSS 覆盖会在可访问性层留下错位。收尾走查靠 `aria-selected` 断言暴露了这一缺陷。
3. **展示口径要收敛成工具函数**：ISO 时间带 `T` 的处理散落在各视图内联代码里,导致四处遗漏;二期末统一进 `utils/format.ts`,后续新页面直接复用。
4. **"能接上接口"不等于"首屏就对"**：分类列翻译依赖懒加载的选项数据,打开弹窗才请求的优化让首屏表格显示兜底文案。涉及展示翻译的数据应在挂载时可用。
5. **浏览器验收是唯一兜底**:R4 曾出现"模板内联 TS 表达式运行时爆炸而构建全绿"、本轮又抓出 Tabbar 高亮与首屏翻译两个结构正常但语义错误的案例——DOM 快照断言(选中态、文案)应成为走查的标准动作,而非只看页面是否渲染。

## 五、遗留与后置候选(非承诺)

1. 组件库按需引入/分包压缩主包体积;
2. SubmitBar 与 Tabbar 的 6px 视觉缝隙(见 R4 记录)如追求像素级贴合可用共享 CSS 变量解决;
3. 自动化测试仍以 Spring 上下文为主,前端无 E2E,若后续能力扩展建议先给登录/守卫链路补最小脚本;
4. 后端支付、统计、排班等模块仍未实现,前端不含这些入口属于契约一致,不是缺口。
