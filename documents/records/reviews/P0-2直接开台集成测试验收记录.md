# P0-2 直接开台集成测试验收记录

> 验收日期：2026-08-29
> 范围：后端首条真实 Service/数据库集成测试
> 计划：[`../../planning/project-development-plan.md`](../../planning/project-development-plan.md)

## 1. 实现内容

新增 `backend/src/test/java/com/foodflow/module/diningsession/service/DiningSessionServiceIntegrationTest.java`，使用 `@SpringBootTest` 加载完整 Spring Boot 上下文，注入真实 `DiningSessionService`、`DiningTableMapper`、`DiningSessionMapper` 和 `UserMapper`。

每个测试创建带唯一桌号和手机号的临时数据，并通过 `@Transactional` 在测试结束后回滚；`@AfterEach` 清理 `LoginContext`，避免线程级登录信息泄漏到其他测试。

## 2. 覆盖场景

| 场景 | 断言 |
| --- | --- |
| 空闲桌直接开台 | 返回等待中会话；桌位变为等待中并绑定会话；会话归属用户和桌位且保持激活 |
| 桌位已被使用 | 第二个用户收到“该桌位已被使用”；原会话和桌位绑定不变；没有新增会话 |
| 用户已有活跃会话 | 第二次开台收到“当前用户已存在用餐会话”；第二桌保持空闲；用户仍只有一个活跃会话 |

## 3. 验收命令

在 MySQL/Redis 开发容器运行、Spring Boot 不占用测试端口的情况下执行：

```bash
cd backend
./mvnw -q -Dtest=DiningSessionServiceIntegrationTest test
./mvnw -q test
```

结果：新增测试 3/3 通过；完整后端测试通过。Surefire 报告位于 `backend/target/surefire-reports/`。

## 4. 当前边界与 P0-3 铺垫

- 当前测试使用 `application-dev.yaml` 的本机 MySQL/Redis，因此仍依赖开发容器、已有 schema 和本机密码配置。
- 测试没有 Mock 业务 Service，后续迁移 Testcontainers 时应保留测试方法和数据库断言，只替换测试环境启动方式。
- P0-3 需要增加测试专用 profile、MySQL/Redis Testcontainers 依赖和容器生命周期配置，确保测试不读取或污染开发数据。
- 当前测试仍按现有通用 `BUSINESS_ERROR` 和中文消息断言；稳定领域错误码属于 P0-5，届时应补充错误码断言而不是删除业务状态断言。
