## 四、验收中发现并修复的缺陷

1. **type-check 是空验证**:根 `tsconfig.json` 为 `"files": []` 的纯引用结构,`vue-tsc --noEmit`(不带 `-b`)实际检查零文件,R1-R4 记录的"type-check 通过"因此不含类型信息。改脚本为 `vue-tsc -b` 后暴露 4 个真实类型错误:`admin-resources` 未再导出 `TableRequest/TableVO` 导致 TablesManageView 引用报错(TS2459)、菜单页与预约页各一个未使用变量(TS6133),均已修复。教训:引用型 tsconfig 必须用 `-b` 才能落到子工程;"构建通过"(`vite build` 不做类型检查)不能替代类型检查证据。
2. **底部导航高亮错误**:Tabbar 未接路由同步,选中态恒为 0("首页"),原实现仅用一条 CSS 把首页洗灰,结果是任何业务页自己的 Tab 都不高亮、可访问性树报错。修复:由当前路由路径推导选中下标并单向绑定 `model-value`;账户中心等非导航页返回 -1 全不点亮。教训:组件库的 route 高亮规则要么整体启用(route 模式),要么完全自管(v-model),混用默认行为只补 CSS 会留下双错位。
3. **时间展示口径不一致**:顾客端预约列表/结果面板、管理端预约表格/抽屉直接渲染 ISO 原串(如 `2026-08-26T12:00:00`)。新建 `utils/format.ts` 统一换空格,不再各页面内联 `replace('T', ' ')`。
4. **菜品分类列首屏显示"分类 N"**:分类下拉选项按"打开表单时懒加载",首次进页时名称翻译失败落入兜底文案。修复:`onMounted` 同时预载列表与分类选项,懒加载守卫保留。
5. **pnpm lint 幽灵命令**:开发流程手册验收清单中的 `pnpm lint` 从未存在,二期立项审查已指出,本轮随手册修正一并清除。
