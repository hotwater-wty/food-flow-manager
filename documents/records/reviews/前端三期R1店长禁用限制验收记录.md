## 验收证据

- `./mvnw -q compile` 退出码 0;`vue-tsc -b` 退出码 0;`vite build` 成功(仅既有的 chunk 体积警告);`git diff --check` 干净。
- 后端容器重建(`docker compose up -d --build food-flow-manager`)后 health UP。
- API 直调(店长 token,`POST /api/admin/employees/1/disable`):返回 `{"code":0,"msg":"店长账号不可禁用"}`——守卫生效。
- 普通路径不受影响:创建测试店员(19999990001,id=3)→ 禁用成功 → 启用成功;测试账号已从数据库删除,员工表仅剩默认店长。
- 浏览器走查(店长登录 → `/admin/resources/employees`):店长行"禁用"按钮为 `[disabled]` 态,DOM 快照断言通过;截图存档 [`前端三期R1员工页店长禁用标灰.png`](前端三期R1员工页店长禁用标灰.png)。

## 说明与遗留

- 自我禁用守卫在当前权限模型下属纵深防御:启用/禁用接口仅店长可调,店长禁用自己的请求会先被角色守卫拦截;保留该守卫是为未来角色调整时仍安全。
- 店长账号调整仍走数据库(与需求一致),前端与管理接口均不再提供禁用入口。
