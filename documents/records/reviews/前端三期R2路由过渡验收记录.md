## 改动清单

| 文件 | 改动 |
| --- | --- |
| `frontend/src/layouts/AdminLayout.vue` | 内容区路由出口改为 `<RouterView v-slot>` + `<Transition name="fade-transform" mode="out-in">` |
| `frontend/src/layouts/CustomerLayout.vue` | 同上,`name="fade"` 轻量淡入淡出 |
| `frontend/src/style.css` | 追加两组过渡类(fade-transform:透明度+12px 位移;fade:仅透明度)与 `prefers-reduced-motion` 降级守卫 |

## 实现要点

- 改造前扫描了 `src/views/**` 与 `src/layouts/**` 共 19 个 SFC,确认全部单根节点(Vue `<Transition>` 动画的前提)。
- `mode="out-in"` 先播完离开动画再进入,避免两页重叠跳动。
- 未引入 keep-alive(计划已确认:页面缓存语义另议,避免购物车等状态被意外冻结)。
- 过渡类放全局 `style.css`(过渡类挂在路由组件根元素上,跨布局复用,不宜放布局 scoped 样式)。

## 验收证据

- `vue-tsc -b`、`vite build`、`git diff --check` 全部通过。
- 浏览器行为断言(DOM 快照/属性读取):
  - 管理端:员工管理 → 订单处理,内容区根元素捕获到 `fade-transform-enter-active fade-transform-enter-to`,落在 `/admin/orders`。
  - 顾客端:点餐 → 订单,捕获到离开元素 `fade-leave-active fade-leave-to`,随后 `/customer/orders` 正常渲染。
- 登录页与 404 在布局之外,不参与过渡,导航行为不受影响(走查确认)。
