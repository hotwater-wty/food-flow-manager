# 顾客选座与商户端操作反馈改造计划

> 计划版本：2026-08-29 v2
> 状态：已完成并通过自动化与关键浏览器/API 验收
> 上游基线：`documents/CURRENT.md`、`documents/frontend/03-页面地图与交互状态.md`、`documents/frontend/05-前端工程与接口契约.md`

## 1. 阶段决策

本阶段暂停二维码生成、摄像头扫码和图片解码方案，顾客到店后直接在首页选择空闲桌位并确认开台。`/session` 不删除，作为兼容入口复用相同组件。

管理端将所有按钮写操作统一为“loading 与互斥锁 → HTTP 结果通知 → 成功后重新 GET”的流程。SSE 只提示用户下单、预约和到店等外部业务变化，不能替代当前按钮请求的即时结果。

## 2. 已实现范围

### C1 顾客首页选座

- 未登录首页不请求受保护接口，只显示登录和预约入口。
- 已登录首页并行查询当前会话与 `GET /api/user/tables`。
- 无会话时展示空闲桌位，点击桌位后确认，再调用 `POST /api/user/tables/{tableId}/sessions`。
- 请求期间显示 loading 并禁止重复提交；成功后跳转 `/menu`。
- 有会话时显示绑定桌位、会话状态和“去点餐”。
- `/session` 复用同一组件；菜单无会话提醒跳转首页。
- 暂不展示被占用、已预约或禁用桌位；该能力等待后端提供正式的全状态查询接口。

### A1 响应契约和统一反馈

- `Result<T>` 增加可选 `errorCode`；成功仍为 `code=1`，失败仍为 `code=0`。
- 管理端读取接口要求成功且 `data` 非空；写接口允许 `code=1 && data=null`。
- 业务错误、HTTP 错误、超时和断网统一转换成 `OperationError`。
- 错误详情包含错误码、类型、HTTP 状态、请求方法/路径、后端消息和发生时间。
- 桌位、分类、菜品、预约、员工、订单状态、会话取消和清台均接入统一操作流程。
- 成功后立即重新查询列表；刷新失败时保留操作成功通知并额外提示手动刷新。
- 查询首屏或详情失败仍由页面错误区域表达；写操作不再写入页面 `el-alert`，避免重复反馈。

### R1 布局级 SSE

- `AdminLayout` 持有管理端唯一 `EventSource`。
- 连接前通过员工 JWT 获取 60 秒一次性 ticket。
- 断线后关闭旧连接、重新申请 ticket，并按 1 秒、2 秒、5 秒退避重连。
- 事件 Store 广播 `new-order`、`new-reservation`、`reservation-check-in`；关联页面静默 GET 最新数据。
- 事件不携带业务详情，REST 查询仍是事实来源。
- 订单、会话和仪表盘取消 20 秒轮询；保留浏览器重新聚焦时的静默刷新兜底。
- 业务事件在事务提交后发布；回滚不发布。
- 测试事件只允许 `dev`/`test` profile；当前 ticket 和 emitter 仍为单实例内存实现。

## 3. 验收条件

### 自动化

```bash
cd backend && ./mvnw test -q
pnpm type-check
pnpm lint
pnpm format:check
pnpm -r build
pnpm test
pnpm test:e2e
git diff --check
```

新增覆盖：写响应空数据成功、查询空数据失败、业务/HTTP/超时归一化、Result 错误码、ticket 过期与重复消费、事务回滚不发布。

### 浏览器

1. 未登录首页无 `/api/user/tables` 请求；登录回首页后显示空闲桌位。
2. 选桌后出现确认框；确认期间按钮 loading；成功后进入菜单。
3. 菜单无会话提示跳回首页；`/session` 同样可选座。
4. 桌位 Z99 禁用时只有一次写请求，按钮 loading，成功通知为“桌位 Z99 已禁用”，随后自动 GET 并显示禁用状态。
5. 失败通知可点击打开错误详情；超时显示 `NETWORK_TIMEOUT`。
6. 管理布局只有一个 SSE 连接；断线重新申请 ticket，登出后关闭。
7. 外部新订单/预约/到店事件只触发静默查询，不覆盖当前按钮反馈。

## 4. 已知边界与后续事项

- 二维码、摄像头与图片扫码方案已暂停，不作为当前入口。
- 后端旧 `BusinessException(String)` 暂用通用 `BUSINESS_ERROR`；重点冲突的细分编码另开后端治理切片。
- SSE 按单实例验收；Redis Pub/Sub、多实例连接共享、nginx 缓冲和长连接超时属于部署计划。
- 全部桌位及状态展示需要新的顾客只读接口，前端不得从空闲列表伪造占用状态。
