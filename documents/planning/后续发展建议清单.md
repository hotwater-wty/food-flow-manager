# 后续发展建议清单

> 撰写日期:2026-08-28(前端拆分收口后)
> 性质:候选清单,非承诺、不自动开工;每项启动前先立切片并核对真实后端契约
> 维护约定:启动某项时把它移入对应阶段的计划文档;完成或作废时在本文标注结论

## 一、前端还有哪些需要优化的(优先)

| # | 事项 | 说明 | 建议优先级 |
| --- | --- | --- | --- |
| F1 | 组件库按需引入与构建分包 | 两端 main.ts 仍是全量引入;admin 主包 964K(未压缩)。用 unplugin-vue-components/unplugin-auto-import 按需引入,或 manualChunks 拆 vendor,预期显著减小首屏 | 高(拆分后独立做,互不影响) |
| F2 | 最小 E2E 脚本 | 登录→守卫→核心页渲染的自动化冒烟(Playwright),双应用各一份;拆分后 URL 变了,正是补测试的时机 | 高 |
| F3 | 统一 lint/format | 工程仍无 ESLint/Prettier;双应用并行开发后风格漂移风险翻倍,先补 flat config + husky pre-commit | 高 |
| F4 | 顾客端列表分页 | 顾客订单/预约仍全量拉取;数据增长后首屏变慢。后端 `GET /api/user/orders` 等是否支持分页需先核对契约,不支持则顺带加参数(小后端改动) | 中 |
| F5 | 购物车状态入 Pinia 或页面缓存 | 目前购物车是菜单页级 ref,切走即丢;二选一:store 持久化(推荐,可跨页)或 keep-alive(需先讨论缓存语义) | 中 |
| F6 | 全局网络错误提示与拦截器增强 | axios 只处理 401;超时/断网无统一 toast。顺带把 baseURL/超时做成两端各自环境配置 | 中 |
| F7 | shared 包的契约测试 | shared 是双端共同依赖,给它加一份类型/映射的最小单测(vitest),防止改映射表弄坏另一端 | 中 |
| F8 | 视觉细节遗留 | SubmitBar 与 Tabbar 6px 缝隙;菜品表单未覆盖"售罄"状态;el-dialog 关闭动画 DOM 残留 | 低 |
| F9 | 管理端仪表盘增强 | 现为零依赖呈现;若要趋势图(近7日订单/营收折线)需引入 ECharts 并增加统计端点(涉及后端,见 B3) | 低(随 B3 一起) |
| F10 | 删除 customer 的 stores/app.ts 占位 | 无引用,顺手清理 | 低 |

## 二、后端预备拆分模块前,功能上还需要添加或优化的

| # | 事项 | 说明 | 建议优先级 |
| --- | --- | --- | --- |
| B1 | 顾客端订单/预约分页接口 | 若 `GET /api/user/orders` 不支持分页参数,补 pageNo/pageSize(为 F4 的前置) | 高 |
| B2 | 近 7 日趋势统计端点 | `GET /api/admin/statistics/trend`:按天聚合订单数与营收;仪表盘折线图的数据源,SQL 已有 create_time 索引 | 中 |
| B3 | 通知机制(WebSocket/SSE 起步) | 工作台目前 20 秒轮询;后端解冻后加 SSE 推送"新订单/预约到店"事件,前端把轮询降级为兜底 | 中 |
| B4 | 顾客账号禁用管理端点 | `UserStatusEnum` 存在但无任何接口可禁用顾客;风控场景需要,配套管理员操作审计 | 中 |
| B5 | 员工信息编辑与离职流转 | `EmployeeStatusEnum` 有"离职"但接口只有启停;`// TODO 更新员工信息` 仍在 EmployeeServiceImpl 里 | 中 |
| B6 | 操作审计日志 | 店长/店员的写操作(改价、启停、取消)无留痕;微服务拆分前补齐,拆开后补成本翻倍 | 中 |
| B7 | 接口幂等性全覆盖 | 仅下单有 X-Submit-Token;预约取消、状态推进等写操作可评估是否需要 | 低 |
| B8 | 模块边界硬化(拆分预演) | 现按 module 包组织;拆微服务前先禁止跨 module 直连 Mapper(必须走 Service),可先用 ArchUnit 测试固化边界 | 低(但拆分前必做) |
| B9 | 统一异常码 | 目前 BusinessException 只带 msg;拆微服务后跨服务排错需要业务错误码字段 | 低 |
| B10 | JWT 刷新/登出机制 | 7 天固定有效、无 refresh;双端独立部署后 token 失效体验问题会放大 | 低 |
