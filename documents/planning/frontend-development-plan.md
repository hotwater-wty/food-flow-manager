## 1. 目标与现实边界

本计划面向 Vue 3 + TypeScript 基础尚未完整、但希望通过项目实践快速形成工程能力的学习过程。目标不是先把课程全部学完，而是在真实后端接口上逐步完成一个可演示的顾客端和商户端前端，同时把每次遇到的知识点转化为可复用理解。

当前仓库没有前端源码。首个阶段只建立可运行工程和最小基础，不直接生成完整业务页面。

## 2. 默认节奏

每个切片遵循：

```text
确认业务故事与后端契约
  -> 明确本次唯一目标
  -> 拆成小块编码
  -> 每块解释 Vue/TypeScript/HTTP 知识
  -> 用户运行、阅读和提问
  -> 类型检查、构建、浏览器验收
  -> 更新文档与学习记录
  -> Git 检查点
```

遇到基础知识缺口时，优先在当前代码中解释其作用，再决定是即时补课还是回看课程。若某个基础缺口会影响后续架构判断，则暂停编码先补齐。

## 3. 阶段路线

### 阶段 0：启动前核对

产出：后端认证契约核对、开发账号/启动条件确认、Node/pnpm 环境确认、前端工程目录约定。

验收：能明确登录接口的请求字段、响应字段、Token 保存方式和错误边界；不修改后端源码。

### 阶段 1：建立前端工程骨架

产出：Vue 3 + TypeScript + Vite 工程、路由、Pinia、Axios、环境变量、开发代理、基础类型和最小启动页。

学习重点：目录结构、`createApp`、组件、`ref`/`computed`、路由、Store、异步请求、TypeScript 类型声明。

验收：`pnpm install`、`pnpm type-check`、`pnpm build`、浏览器打开首页均成功。

### 阶段 2：顾客认证切片

产出：顾客登录和注册，Token 持久化，401 返回登录，最小用户状态展示。

学习重点：表单绑定、事件、响应式状态、Promise、Axios 拦截器、路由守卫。

验收：使用真实后端完成注册或登录，刷新页面仍保持登录，清除 Token 后受保护路由回登录页。

### 阶段 3：顾客预约与开台切片

产出：空闲桌位、预约创建/取消、模拟扫码、当前会话。

学习重点：列表渲染、条件渲染、查询参数、一次性提交令牌、业务状态映射和错误恢复。

### 阶段 4：顾客点餐与订单切片

产出：启售菜品、分类、前端购物车、创建订单、订单列表和详情。

学习重点：跨页面共享状态、数组与对象类型、金额展示、提交状态和后端分页/非分页边界。

### 阶段 5：商户订单与会话切片

产出：员工登录、订单工作台、状态推进、会话列表、取消等待和清台。

学习重点：管理端布局、表格/分页、角色权限、轮询或手动刷新、状态机约束。

### 阶段 6：第二批资料与工程收尾

产出：桌位、菜品、分类、员工管理等第二批页面；补齐测试、构建、浏览器验收、文档和复盘。


## 5. 当前首个工作项

当前工作项是“阶段 0：启动前核对”。已确认的后端认证事实如下：

| 场景 | 请求 | 成功响应 |
| --- | --- | --- |
| 顾客注册 | `POST /api/user/auth/register`，`phone/password/nickname` | `userId/phone/nickname/status` |
| 顾客登录 | `POST /api/user/auth/login`，`phone/password` | `userId/phone/nickname/status/token` |
| 员工登录 | `POST /api/admin/auth/login`，`phone/password` | `employeeId/phone/name/role/status/token` |

统一外层响应为 `Result<T>`：`code=1` 成功，`code=0` 业务失败；认证失败还可能返回 HTTP 401，角色不匹配返回 HTTP 403。前端第一阶段不能假定存在短信登录，也不能把员工注册误当作公开注册。

## 6. 需要用户参与的检查点

阶段 0 环境核对结果（2026-08-22）：

- Node.js：`v22.23.2`，可用。
- pnpm：`11.19.0`，可用。
- 根目录 `frontend/`：尚未创建，符合当前计划。
- 后端 `http://localhost:8080/actuator/health`：当前不可访问，服务未启动。
- Docker Compose：当前 Docker daemon 不可用；不能把容器启动当作已验证前置条件。
- 本地开发配置依赖 MySQL `localhost:3306` 和 Redis `192.168.100.129:6379`，启动后端前需确认这两个依赖可访问，不能擅自修改配置中的凭据或地址。

在进入阶段 1 前，需要由用户确认后端依赖的启动方式或先启动 MySQL、Redis 并让后端可访问认证接口。Node.js/pnpm 已满足创建最小工程的条件，但没有真实后端时只能做静态骨架，不能完成第一条真实业务验收。
