# 项目文档组织与格式规范

> 文档状态：当前维护规范
> 更新日期：2026-08-22

本文档规定 `food-flow-manager` 的文档职责、事实来源、状态标记和归档方式。目标是让当前设计、开发计划和历史记录彼此分离，避免旧阶段计划继续影响实现判断。

## 1. 事实来源优先级

发生冲突时按以下顺序处理：

1. 当前源码、测试和可复现运行结果。
2. `pom.xml`、`application*.yaml`、`Dockerfile`、`docker-compose.yml` 和 `assets/schema.sql`。
3. 项目根目录 `README.md` 与 `documents/CURRENT.md`。
4. `documents/architecture/` 和 `documents/frontend/` 中标记为“当前”的设计或契约。
5. `documents/records/` 中的过程证据。
6. `documents/archive/` 中的历史计划和草稿。

源码与当前文档不一致时，不能只改文档来掩盖实现问题。先确认哪一方代表预期行为，再同步代码、测试和文档；仅做文档校准时，以已经存在的实现为准并记录未实现项。

## 2. 目录职责

| 位置 | 职责 | 是否作为当前事实 |
| --- | --- | --- |
| `documents/CURRENT.md` | 当前阶段、权威入口、下一验收点 | 是 |
| `documents/architecture/` | 已落地架构、接口、数据模型和稳定设计 | 是 |
| `documents/frontend/` | 尚未实现的前端产品、交互、工程和验收规格 | 是，代表目标规格 |
| `documents/planning/` | 当前跨模块计划和任务池 | 是，代表计划 |
| `documents/guides/` | 文档与开发工作方法、模板 | 是 |
| `documents/records/` | 问题、决策、实践、专题和阶段复盘 | 否，代表形成过程 |
| `documents/archive/` | 已完成阶段、被替代方案和草稿 | 否，只用于追溯 |

`assets/` 只保留运行时资产。当前 `assets/schema.sql` 被 Docker Compose 直接挂载，不迁入文档目录。

## 3. 文档状态标记

非纯索引文档应在标题后使用以下四种状态之一：

```markdown
> 文档状态：当前事实
> 校准日期：yyyy-MM-dd
> 事实来源：源码 / 配置 / schema / 运行验证
```

```markdown
> 文档状态：当前计划
> 更新日期：yyyy-MM-dd
> 完成标准：可观察的验收结果
```

```markdown
> 文档状态：历史记录
> 记录阶段：V1 / V2 / 具体日期
> 当前事实入口：[链接]
```

```markdown
> 文档状态：历史归档（只读）
> 原适用阶段：V1 / V2 / 草稿期
> 当前事实入口：[链接]
```

## 4. 内容格式

- 标题说明文档对象，不把日期和状态塞进文件名。
- 开头先写状态、用途和不承担的职责。
- 当前事实使用确定语气；计划使用“目标、范围、验收”；历史记录保留当时语境。
- 接口路径、类名、字段、命令和文件路径使用反引号。
- 只在结构确实复杂时使用表格；长篇 JSON 示例优先由 OpenAPI 提供。
- 同一事实只维护一个完整版本，其他文档写摘要和相对链接。
- “已完成”必须能由源码、测试、配置或运行证据支持；枚举中存在值不等于业务接口已经使用。

## 5. 更新触发条件

| 变化 | 至少更新 |
| --- | --- |
| Controller 路径、方法、请求头或权限变化 | 接口清单、前端接口契约、README（若对外入口变化） |
| DTO、VO、分页或状态码变化 | 接口规范、接口清单、前端状态映射 |
| 表、索引或状态字段变化 | 领域模型、`schema.sql`、设计更新日志 |
| 依赖、缓存或部署方式变化 | 技术选型、部署专题、README |
| 包或模块职责变化 | 包结构设计 |
| 前端切片完成或范围变化 | `CURRENT.md`、前端计划、README |
| 阶段结束 | 新增复盘，计划移入 `archive/`，更新 `CURRENT.md` |

纯注释、格式化或不改变行为的内部重构通常不需要更新产品与接口文档。

## 6. 归档流程

1. 确认内容已经完成、取消或被新方案替代。
2. 把仍有效的结论提炼到当前事实文档，不复制整篇旧文。
3. 在旧文标题后加入历史归档标记、原适用阶段和当前入口。
4. 按 `plans/`、`tasks/`、`requirements/` 或 `drafts/` 移入 `documents/archive/`。
5. 修正入口链接，确保 README 和 `CURRENT.md` 不再把归档文档当作当前任务。

归档文档原则上不继续维护内容；只修复断链、补充历史边界或纠正会造成安全风险的错误。

## 7. 新建文档检查

1. 是否能更新现有权威文档？能则不新建。
2. 内容描述当前事实、目标规格、执行计划还是历史过程？
3. 是否有明确更新触发条件和停止标准？
4. 是否重复了 OpenAPI、源码或 README 已经完整表达的内容？

无法回答这些问题的临时想法先进入当前任务说明，不直接创建平级 Markdown。
