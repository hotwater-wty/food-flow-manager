# 当前项目开发流程

> 文档状态：当前维护规范
> 更新日期：2026-08-22

本文档适用于当前 `food-flow-manager` 的增量开发。后端核心闭环、Redis、分页、防重复提交和 Docker Compose 已落地；当前建设重点是前端最小可演示闭环。历史 V1/V2 从零开发过程见 `documents/archive/` 和 `documents/records/reviews/`。

## 1. 开发原则

- 每次只推进一个可独立验收的纵向切片。
- 代码和运行结果是当前事实，计划不能被写成已完成。
- 先复用现有接口和业务规则，发现契约缺口后再决定是否修改后端。
- 成功路径、失败路径、权限、加载和重复提交属于同一个切片。
- 完成意味着有命令结果和可操作验收证据，不等于文件已经生成。

## 2. 当前基线

后端已经具备：

- 用户、员工认证和基于 JWT 的端侧/店长权限隔离。
- 桌位、预约、开台会话、菜品分类、菜品和堂食订单业务。
- 条件更新、事务和活跃会话唯一索引。
- 管理端主要列表分页。
- 菜品、分类、账号状态缓存和 Redis 一次性提交令牌。
- Knife4j/OpenAPI、MySQL/Redis/应用的 Docker Compose 部署。

当前未完成：

- `frontend/` 仍为空，没有 Vue 工程或页面。
- 自动化测试只有 Spring 上下文测试，核心业务场景覆盖不足。
- MQ、定时任务、支付、短信、排班、操作日志和 Spring Security 未落地。

## 3. 单个切片流程

### 3.1 确认目标

任务说明必须包含：用户故事、唯一目标、允许修改范围、后端契约、成功/失败场景和完成标准。前端顺序以 `documents/frontend/06-纵向切片开发计划.md` 为准。

### 3.2 核对当前事实

开始编码前按需读取：

1. `documents/CURRENT.md` 和相关前端规格。
2. 对应 Controller、DTO、VO、枚举和 Service 业务校验。
3. `WebMvcConfig` 与 `JwtTokenInterceptor` 的权限边界。
4. OpenAPI 或运行中的真实响应；设计稿不能替代实际接口。

需要记录的契约包括路径、方法、请求头、请求体、响应形状、状态码、权限、幂等要求和业务冲突。

### 3.3 实现

- 前端按页面、状态管理、请求封装和真实接口一起完成，不长期保留假数据。
- 后端改动保持 Controller、Service、Mapper/缓存职责清晰，跨表状态变化使用事务并保留条件更新。
- 新依赖必须对应当前切片的明确需求，不为候选功能提前搭框架。
- 不顺手扩展无关页面、接口或业务状态。

### 3.4 验证

后端改动至少执行：

```bash
./mvnw test
```

前端工程建立后至少执行：

```bash
pnpm type-check
pnpm lint
pnpm build
```

涉及用户流程时还需在浏览器验证真实后端，包括正常流程、无数据、参数错误、401、403、业务冲突和重复提交。关键页面检查 390x844 与 1440x900。

### 3.5 文档与检查点

- 行为或契约变化时同步当前文档。
- 阶段状态变化时更新 `documents/CURRENT.md`。
- 有复用价值的问题或取舍写入 `records/`。
- 检查 `git diff`、构建与验收证据后，再建立 Git 提交检查点。

## 4. 前端首期切片顺序

1. 建立 Vue 3 + TypeScript + Vite 工程、路由、Pinia、Axios、代理和基础类型。
2. 顾客注册/登录和 Token 生命周期。
3. 顾客桌位与预约，包含 `create-reservation` 提交令牌。
4. 预约到店与非预约扫码开台、当前会话。
5. 菜单、前端购物车和订单提交，包含 `create-order` 提交令牌。
6. 顾客订单列表与详情。
7. 员工登录、商户订单分页与顺序状态推进。
8. 商户会话分页、取消等待和清台。
9. 资料管理等第二批功能，仅在首条闭环验收后启动。

## 5. 后端增强进入条件

后端候选增强先写入 `documents/planning/`，满足以下条件才进入开发：

- 前端联调暴露真实接口或数据缺口。
- 自动化测试需要可重复的数据与隔离能力。
- 运行或部署出现可复现故障。
- 新能力有明确业务场景和可验证结果。

不得把 MQ、定时任务、Spring Security 或复杂缓存治理仅作为技术名词加入当前阶段。

## 6. 完成定义

- 目标范围内的代码和配置完整。
- 真实接口成功路径可操作。
- 关键失败、权限和并发/重复提交边界已验证。
- 自动检查通过，未掩盖失败。
- 当前文档与实现一致，历史资料未被当作当前依据。
- 已知限制明确写出，不以候选计划充当成果。
