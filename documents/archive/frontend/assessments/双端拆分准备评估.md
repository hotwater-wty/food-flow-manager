# 双端拆分准备评估

> 撰写日期:2026-08-28(前端三期 P3-R6 交付物)

> 上游:用户决策"本阶段只做准备"(见 `../plans/frontend-phase3-plan.md` 已确认决策表)

## 1. 结论摘要

- **现状**:单 Vite 应用,顾客端(用户端)与商户端(管理端)靠目录约定分离(`views/Customer*` + Vant vs `views/Admin*`/`admin/` + Element Plus),后端已按 `/api/user/**` 与 `/api/admin/**` 干净分组,拆分天然对齐 API 边界。
- **建议时机**:后端微服务拆分启动时同步执行;单独提前拆的收益(构建隔离、部署独立)小于成本(共享层复制、双份构建配置)。
- **预估工作量**:R1-R4 切片量级(非 R5);最大风险点是 `http.ts` 的两处"嗅探"逻辑,拆分后自然消失但迁移期易漏。

## 2. 耦合点清单(拆分时需要手术的位置)

| # | 耦合点 | 现状 | 拆分动作 | 风险 |
| --- | --- | --- | --- | --- |
| 1 | `services/http.ts` | 单 axios 实例服务双端:按 `url.startsWith('/admin')` 嗅探选 token;401 时按 `router.currentRoute.path` 嗅探跳哪个登录页 | 每个工程一份 `http.ts`,硬编码自己的 baseURL/token key/登录路由,嗅探逻辑整体删除 | 低;迁移期注意别把两份拦截器写串 |
| 2 | `types/api.ts` | 单文件双端 DTO/VO | 按域拆分复制;`Result`/`PageResult` 等公共件双份维护 | 低;字段漂移需靠契约文档(05)对齐 |
| 3 | `utils/status.ts` / `order-status.ts` / `format.ts` | 双端共用 | 各自取所需复制;或抽 npm 共享包(见 §4) | 低 |
| 4 | `router/index.ts` | 单路由表双域守卫(`requiresAuth` vs `requiresAdminAuth`) | 拆两个路由文件;守卫逻辑各自简化 | 低 |
| 5 | `styles/tokens.css` | 一份令牌文件按 `--color-bg-customer`/`--color-bg-admin` 分区 | 令牌分区各自成文件 | 低 |
| 6 | 依赖树 | main.ts 全量引入 Element Plus 与 Vant | 拆分后各工程只装自己的 UI 库,主包体积天然减半 | 无 |
| 7 | 登录页/404 | 布局外共享 | 各自持有 | 低 |

已消除的耦合(R4 完成):`formatPrice`/标签映射的跨页复制、手写分页状态机——共享层收敛后拆分就是"按目录搬家",不是"边拆边理遗留"。

## 3. 建议拆分步骤草案

1. 前置:确认后端微服务拆分方案(哪些域先拆),前端按对应节奏拆,避免前端先拆成两个单块。
2. 目录形态二选一(见 §4 决策项)。
3. 顾客端工程先拆(范围更独立:Vant + 4 个 Tab 页),验证构建/部署链路。
4. 商户端工程复制拆出。
5. 双端各自的 404、守卫、`http.ts` 收尾;删除根工程或保留为壳(决策项)。
6. 文档同步:03 页面地图、05 契约、README 启动方式。

## 4. 待决策项(拆分计划立项时确定)

| 决策项 | 选项 A | 选项 B |
| --- | --- | --- |
| 仓库形态 | 单仓库 pnpm workspace(`apps/customer` + `apps/admin` + 可选 `packages/shared`) | 两个独立仓库 |
| 共享代码 | 抽 `packages/shared`(types/utils),需要 workspace 构建链 | 直接复制,接受双份漂移 |
| 根工程 | 保留为只含 README/文档的壳 | 删除 |

建议:选项 A(同仓库 workspace)——个人项目协作成本最低,契约文档仍在同一 `documents/` 树内。

## 5. 与后端微服务的对应关系(前瞻,非承诺)

当前后端为单应用 + 模块分包(`module/user`、`module/employee`、`module/diningorder` 等)。若未来按"用户/订单/桌台会话/统计"拆微服务,前端拆分后的两个工程按 API 网关前缀路由即可,前端无需感知服务实例数——这也是"前端先按用户/商户拆、不按业务域拆"的理由。
