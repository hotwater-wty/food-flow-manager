# 后端接口规范

> 文档状态：当前事实
> 校准日期：2026-08-22
> 事实来源：Controller、DTO、VO、拦截器、全局异常处理器和 OpenAPI 配置

## 1. 通用响应

所有业务 Controller 返回 `Result<T>`：

```json
{"code":1,"msg":"success","data":{}}
```

- `code=1`：业务成功；`code=0`：业务或处理失败。
- `msg`：成功提示或异常消息。
- `data`：成功数据；无数据成功响应通常为 `null`。
- `BusinessException`、参数校验异常、未处理异常和重复键异常由 `GlobalExceptionHandler` 转为 `Result.error(...)`。
- JWT 拦截失败直接返回 HTTP 401 或 403，未经过 `Result` 包装。

## 2. 分页

管理端分页接口返回 `Result<PageResult<T>>`：

```json
{"total":100,"pageNo":1,"pageSize":10,"records":[]}
```

`pageNo` 默认 1，`pageSize` 默认 10，最大 500。当前管理端分页接口包括订单、预约、会话、菜品、菜品分类、桌位和员工；用户端订单、预约、菜品、分类和桌位接口按各自 Controller 返回列表或对象。

## 3. 认证、权限和令牌

登录、用户注册、员工注册（店长专属）路径由 `WebMvcConfig` 控制是否免 JWT。其他 `/api/**` 请求需携带：

```http
Authorization: Bearer <jwt>
```

用户端只接受 `loginType=USER`，管理端只接受 `loginType=EMPLOYEE`。员工角色 `STAFF=1`、`MANAGER=2`；员工管理、员工注册和删除桌位等路径由拦截器额外限制店长。

用户创建预约和创建订单前必须调用：

```http
POST /api/user/submit-token
Content-Type: application/json

{"scene":"create-reservation"}
```

可用场景为 `create-reservation`、`create-order`、`open-session`、`clear-table`；返回令牌有效期 300 秒，写操作通过 `X-Submit-Token` 携带并一次性消费。当前 Controller 已实际接入预约和订单创建；其他场景值已定义但不能据此宣称所有接口均已接入令牌校验。

## 4. 字段与状态

- JSON 使用小驼峰；数据库使用下划线。
- 时间字段由 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")` 等约定序列化。
- 金额和价格为整数分，前端展示时转换为元。
- 用户：`1` 正常，`2` 禁用。
- 员工：`1` 正常，`2` 禁用，`3` 离职。
- 桌位：`0` 空闲，`1` 已预约，`2` 等待中，`3` 用餐中，`4` 禁用。
- 预约：`0` 待到店，`1` 已到店，`2` 已取消，`3` 已超时。
- 会话：`0` 等待中，`1` 用餐中，`2` 已完成，`3` 已取消。
- 菜品：`0` 停售，`1` 启售，`2` 售罄。
- 分类：`1` 启用，`2` 禁用。
- 订单：`1` 已下单，`2` 制作中，`3` 已上齐，`4` 已完成，`5` 已取消；当前管理端状态更新只允许顺序推进，不支持取消。

## 5. 请求规则

- `GET` 查询，`POST` 创建或业务动作，`PUT` 资料整体修改，`DELETE` 删除。
- 当前用户 ID、员工 ID 从登录上下文读取，不由前端作为业务归属字段传入。
- Controller 使用 DTO 和 Bean Validation；具体约束以 DTO 注解为准。
- 列表无数据返回空列表或 `records=[]`；对象不存在通常返回业务错误。
- `X-Submit-Token` 缺失或已消费时返回业务失败，不应自动复用旧令牌。

## 6. OpenAPI 入口

- 页面：`http://localhost:8080/doc.html`
- JSON：`http://localhost:8080/v3/api-docs`
- OpenAPI 分组扫描 `/api/**` 和 `com.foodflow`。

本文件用于解释通用契约；接口字段和实际路径以 Controller、DTO、VO 与 OpenAPI 输出为最终依据。
