# 后端实际包结构与职责

> 文档状态：当前事实
> 校准日期：2026-08-22
> 事实来源：`backend/src/main/java/com/foodflow`

本文描述当前源码，而不是未来推荐目录。包名和模块名变化时，以源码为准并同步本文件。

## 1. 实际结构

```text
com.foodflow
├── FoodFlowManagerApplication.java
├── common
│   ├── constant
│   ├── context
│   ├── controller
│   ├── dto
│   ├── enums
│   ├── exception
│   ├── result
│   ├── service
│   ├── utils
│   └── vo
├── config
├── interceptor
└── module
    ├── user
    ├── employee
    ├── table
    ├── reservation
    ├── diningsession
    ├── dishcategory
    ├── dish
    ├── diningorder
    └── orderitem
```

业务模块通常包含 `controller`、`service`、`service.impl`、`mapper`、`entity`、`dto` 和 `vo`；并非每个模块都必须拥有全部子包。

## 2. 公共层

- `common.constant`：JWT claim 和缓存 key 前缀。
- `common.context`：`LoginContext`、`LoginInfo`，保存请求线程中的登录主体。
- `common.controller`：提交令牌和 favicon 等跨模块 Controller。
- `common.dto`：分页参数和提交令牌参数。
- `common.enums`：状态、角色、登录类型、提交场景和缓存命中状态。
- `common.exception`：`BusinessException` 与 `GlobalExceptionHandler`。
- `common.result`：`Result<T>`、`PageResult<T>`、缓存结果对象。
- `common.service`：提交令牌服务等跨模块业务能力。
- `common.utils`：JWT、密码、编号、缓存工具及各领域 CacheClient。
- `common.vo`：公共响应对象，例如提交令牌响应。

## 3. 配置和拦截器

`config` 当前包含：

- `MyBatisConfig`：MySQL 分页插件，最大单页 500。
- `RedisConfig`：RedisTemplate 序列化配置。
- `PasswordConfig`：密码编码器。
- `WebMvcConfig`：注册 JWT 拦截器，保护 `/api/**`，排除三类登录/注册接口。

`interceptor/JwtTokenInterceptor` 负责：

1. 读取 `Authorization: Bearer ...`。
2. 解析 JWT claim。
3. 按 `/api/user/`、`/api/admin/` 校验登录类型。
4. 校验用户/员工账号状态和店长专属路径。
5. 设置并在请求结束后清理 `LoginContext`。

## 4. 业务模块职责

| 模块 | 当前职责 |
| --- | --- |
| `user` | 普通用户注册、登录和用户数据 |
| `employee` | 员工登录、店长新增/查询/启禁用员工 |
| `table` | 桌位查询、增改删、启用和禁用 |
| `reservation` | 用户预约与取消、管理端查询和异常取消 |
| `diningsession` | 预约到店、扫码占座、当前/管理端会话、取消等待、清台 |
| `dishcategory` | 用户启用分类查询、管理端分类维护 |
| `dish` | 用户启售菜品/详情、管理端菜品维护和状态变更 |
| `diningorder` | 用户下单/查单、管理端查单和顺序更新状态 |
| `orderitem` | 订单明细实体、Mapper、Service 和响应对象 |

跨模块状态变化由主导业务 Service 编排。例如 `DiningSessionServiceImpl` 直接使用订单 Mapper 完成清台相关更新，避免 Service 循环依赖。

## 5. 分层约束

- Controller：接收参数、校验、读取登录上下文、调用 Service 和封装 `Result`。
- Service：负责归属校验、状态机、事务、条件更新、跨表编排和 VO 组装。
- Mapper：数据库访问和必要的批量更新，不承载端侧权限或业务状态语义。
- Entity：数据库映射和枚举状态。
- DTO：请求参数与筛选条件。
- VO：对外响应，不直接暴露数据库实体作为 API 契约。
- CacheClient：集中管理某个领域的 key、序列化、空值缓存和失效策略。

## 6. 当前不存在的规划包

源码中不存在独立的 `security`、`session`、`order`、`Knife4jConfig` 或 `RedisKeyConstant` 包/类。若未来引入完整安全框架、异步领域或模块拆分，应先建立决策记录和迁移计划，不要提前把目录写成当前结构。
