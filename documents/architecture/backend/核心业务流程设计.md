# 核心业务流程与状态机

> 文档状态：当前事实
> 校准日期：2026-08-29
> 事实来源：`backend` 各业务 Service、状态枚举和 `assets/schema.sql`

## 1. 主链路

```text
用户注册/登录
  -> 查看空闲桌位
  -> 创建预约或直接选择空闲桌位
  -> 预约到店或直接开台
  -> 查看启售菜品
  -> 创建堂食订单
  -> 员工推进订单状态
  -> 订单完成后清台释放桌位
```

## 2. 预约与开台

- 创建预约要求桌位空闲、人数不超过容量、预约时间为未来时间；成功后预约为待到店，桌位为已预约。
- 用户取消自己的待到店预约，预约变为已取消，桌位恢复空闲。
- 预约到店要求预约归属当前用户、状态为待到店、请求桌位与预约桌位一致；成功后预约已到店，创建等待中会话，桌位进入等待中。
- 非预约开台要求桌位空闲；当前顾客端由首页选择桌位，成功后创建等待中会话，桌位进入等待中。
- 活跃会话使用 `active_flag=1`，完成或取消后置空；数据库唯一索引限制同一用户和同一桌位同时存在多个活跃会话。

## 3. 下单与订单

- 订单创建要求会话属于当前用户、会话和桌位均为等待中、菜品存在且启售、数量合法。
- 创建订单和明细在事务中完成，订单为已下单；会话和桌位转为用餐中，记录首次下单时间。
- 订单状态只能按 `已下单 -> 制作中 -> 已上齐 -> 已完成` 顺序推进；重复提交同一状态返回当前状态，跳级和取消被拒绝。
- 订单明细保存下单时菜品名称、图片、单价和金额，避免后续菜品资料变化影响历史订单展示。

## 4. 清台与等待释放

- 等待中的会话由员工确认用户离开后执行取消，释放桌位并清空当前会话 ID。
- 用餐中的会话清台前不能存在“已下单”或“制作中”订单；会话完成后，将已上齐订单置为已完成，桌位恢复空闲。
- 清台和取消等待均记录关闭时间和执行员工 ID。
- 当前没有自动超时、自动提醒或订单状态历史表。

## 5. 桌位状态

```text
FREE(0)      -> RESERVED(1) -> WAITING(2) -> DINING(3) -> FREE(0)
     \-> WAITING(2) -------------------------------> FREE(0)
FREE(0) <------------------------------------------ DISABLED(4)
```

- `FREE -> RESERVED`：创建预约。
- `RESERVED -> FREE`：用户取消预约或管理端取消异常预约。
- `RESERVED -> WAITING`：预约用户核验到店。
- `FREE -> WAITING`：非预约选择空闲桌位开台。
- `WAITING -> DINING`：创建首个订单。
- `DINING -> FREE`：员工清台。
- `WAITING -> FREE`：员工取消等待会话。
- `FREE <-> DISABLED`：管理端启用/禁用；业务状态桌位不能禁用、修改或删除。

所有跨表状态变化由事务和条件更新保护，失败时抛出业务错误并回滚。
