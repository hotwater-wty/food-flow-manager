# 后端技术选型与当前依赖

> 文档状态：当前事实
> 校准日期：2026-08-29
> 事实来源：`backend/pom.xml`、`backend/src/main`、配置文件、Docker 配置和根目录 `README.md`

本文记录当前仓库实际使用的后端技术和未实现候选能力。它不再描述从零搭建 V1 的建议清单；新增依赖必须先进入当前计划并有业务验收。

## 1. 项目基线

- 项目：`food-flow-manager` / 膳畅管家。
- 形态：Spring Boot 单体、按业务模块组织的 REST API。
- Java：17。
- 构建：Maven Wrapper。
- 运行端口：`8080`。
- 配置 profile：默认激活 `dev`。
- 数据库：MySQL 8.x，初始化脚本为 `assets/schema.sql`。
- 缓存：Redis，使用 Spring Data Redis。

## 3. 当前实现边界

### 认证与权限

登录成功后返回 JWT。受保护请求使用：

```http
Authorization: Bearer <jwt>
```

拦截器从 `loginType`、`userId`、`employeeId` 和 `role` 判断用户端、管理端及店长专属路径，并把登录信息放入 `LoginContext`。账号状态从数据库和 Redis 状态缓存校验。项目没有使用 Spring Security FilterChain，也没有动态权限表。

### 分页

`MyBatisConfig` 注册 MySQL 分页插件，单页上限为 500。管理端订单、预约、会话、菜品、分类、桌位和员工列表使用 `PageResult<T>`；用户端订单和预约列表目前仍按业务接口返回普通列表，不能笼统宣称“所有列表分页”。

### Redis

当前缓存 Client 覆盖：

- 启售菜品全部列表和分类列表。
- 菜品详情及空值缓存。
- 启用菜品分类列表和详情。
- 用户与员工账号状态。
- 一次性提交令牌，TTL 5 分钟，消费时删除。

缓存不是业务真实数据来源。菜品和分类变更后由 Service 清理相关缓存；会话、订单和预约状态没有统一缓存层，源码中的 TODO 不能当作已完成能力。

### 数据一致性

创建预约、开台、下单和清台使用事务；桌位、预约、会话和订单状态更新包含条件更新。`dining_session` 通过 `(user_id, active_flag)` 与 `(table_id, active_flag)` 唯一约束限制活跃会话。应用仍需对并发异常和数据库约束错误做验证，不能把防重复提交令牌等同于完整幂等系统。

### 实时通知

管理端使用单条布局级 SSE 连接接收新订单、新预约和预约到店事件。员工先用 JWT 调用 ticket 接口，再以一次性 ticket 建立 `EventSource`；事件在事务提交后发布，前端收到事件后重新查询 REST 接口。当前 ticket、连接和事件均为单实例内存实现，没有心跳、多实例共享或可靠投递。

## 4. 未实现候选能力

以下能力当前没有对应实现，不得写成已完成：

- MQ、可靠异步投递和死信处理；当前 SSE 只是在线变化提示。
- 定时任务、预约超时自动处理和自动提醒。
- 支付、短信验证码、购物车持久化、追加订单、退单/改单。
- 排班、操作日志查询和动态权限配置。
- Spring Security 完整认证授权体系。
- 多门店、微服务拆分和复杂可观测性。

候选能力只有在有明确业务场景、代码变更和验收证据后，才能从计划移入当前事实。

## 5. 配置与部署事实

- `backend/src/main/resources/application.yaml` 配置 Spring 应用名、端口、OpenAPI 路径和默认 profile。
- `backend/src/main/resources/application-dev.yaml` 保存本地开发连接配置；本机 Redis 使用 `localhost`，实际部署由 Compose 环境变量覆盖数据库和 Redis 主机。
- `backend/Dockerfile` 在构建阶段执行 Maven Wrapper，运行阶段使用 Java 17 JRE；根目录 Compose 的构建上下文为 `./backend`。
- Compose 通过健康检查后再启动应用，并挂载 `assets/schema.sql` 作为 MySQL 初始化脚本。
- 本地和部署密码仍存在配置示例中，正式环境应改用外部密钥或安全变量；当前文档不把这项治理写成已完成。

## 6. 变更规则

依赖、缓存序列化、认证边界、部署拓扑或配置键变化时，同步更新本文件、受影响专题、README 和必要的过程记录，并在 `backend/` 目录执行 `./mvnw test`。
